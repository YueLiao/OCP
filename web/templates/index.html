How to describe your cipher
Best sources: the arXiv LaTeX source ("Download source" on the paper's abstract page), or the author's reference implementation (it is unambiguous and gives test vectors). PDF works but formulas are often lost, so prefer .tex / .md, or paste just the round-function section.
Three ways to bring a cipher in (LLM connected), all landing in the same read-back + verify review: (1) upload a .tex/.md with the paperclip; (2) paste the text and click Draft; (3) drop the file in the files/ folder, type its name in the box, and click Draft.
Only have a PDF? Convert it first
Convert to Markdown (keeps formulas) with an open-source tool, then paste it here or upload the .md:
· pip install marker-pdf then marker_single paper.pdf --output_dir out/
· or pip install nougat-ocr then nougat paper.pdf -o out/
Short paper: paste the .md and click Draft. Long paper: first ask any LLM to pull out only the spec + test vectors (prompt below), then paste that. Always double-check S-box tables and constants. 
Extract ONLY the cipher specification from the attached pages into clean Markdown. Do not summarize or explain. Include, in order: (1) state layout - block size, word size, number of words, number of rounds; (2) the round function as an ordered list of operations (rotate/shift with direction+amount, xor/and/or/not, modular add, S-box, permutation), using 0-based word indices and stating which words each step reads and writes; (3) every S-box and permutation table verbatim (full length, input 0..2^n-1 -> output); (4) the key schedule and which key words form each round subkey (if a block cipher); (5) any test vectors as input -> output (with key). Preserve all tables and constants exactly.
Tips: use 0-based word indices; say rotation vs shift and the direction; give the full S-box table (input 0..2^n-1 to output); include at least one test vector so the build can be verified.
